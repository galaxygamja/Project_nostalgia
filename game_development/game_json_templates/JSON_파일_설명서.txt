게임 데이터 JSON 파일 설명서
대상 엔진: Godot 4.7.1
문서 버전: 1

======================================================================
1. 이 문서의 목적
======================================================================

이 문서는 game_json_templates 폴더에 들어 있는 20종의 JSON 파일을 인간 개발자가
이해하고 수정할 수 있도록 설명한다.

JSON 표준 문법은 // 또는 /* */ 형식의 주석을 지원하지 않는다. JSON 파일 안에 일반
주석을 넣으면 Godot의 JSON 파서가 파일을 읽지 못할 수 있으므로, 설명은 이 문서에서
관리한다.

게임의 기본 원칙은 다음과 같다.

1) JSON은 데이터와 규칙을 정의한다.
2) Godot 코드는 JSON을 읽고 검사하고 실행한다.
3) JSON 안의 계산식은 GDScript 코드가 아니라 구조화된 연산 데이터다.
4) 원본 JSON 데이터는 런타임에 직접 수정하지 않는다.
5) 변경이 필요한 상태는 duplicate(true)로 깊은 복사한 뒤 수정한다.
6) 새 게임은 initial_game_state.json을 읽어 각 런타임 상태에 값을 대입한다.
7) 저장 및 불러오기는 현재 구현 범위에서 제외한다.


======================================================================
2. 공통 JSON 작성 규칙
======================================================================

[문자 인코딩]
- UTF-8을 사용한다.
- UTF-8 BOM은 사용하지 않는 것을 권장한다.

[들여쓰기]
- 공백 2칸을 사용한다.
- 탭과 공백을 섞지 않는 것을 권장한다.

[이름 규칙]
- JSON 필드 이름은 snake_case를 사용한다.
- 예: current_time, active_character_ids, duration_slots

[공통 최상위 필드]

schema_version
- JSON 형식의 버전을 나타내는 정수다.
- 현재 값은 1이다.
- 향후 JSON 구조가 변경될 때 호환성 검사에 사용한다.

data_type
- 파일에 들어 있는 데이터 종류를 나타낸다.
- 예: character, task, encounter, formula

entries
- 같은 종류의 실제 데이터 정의를 담는 배열이다.
- game_config, initial_game_state, timetable처럼 단일 구조를 사용하는 파일에는 없을 수 있다.

[금지 사항]
- 후행 쉼표를 넣지 않는다.
- NaN, Infinity, 함수 또는 GDScript 코드를 값으로 넣지 않는다.
- 다른 데이터를 참조할 때 화면 표시 이름 대신 ID를 사용한다.
- 동일한 ID를 둘 이상의 파일에서 중복 정의하지 않는다.


======================================================================
3. 조합형 ID 규칙
======================================================================

모든 주요 데이터 ID는 다음 형식을 사용한다.

ABCD_001

ABCD
- 네 개의 알파벳이 각각 별개의 분류 정보를 나타낸다.
- 단어를 네 글자로 축약한 것이 아니다.

001
- 동일한 네 글자 조합 안에서의 일련번호다.
- 000은 시스템 예약 번호로 비워두는 것을 권장한다.

정규식:
^[A-Z]{4}_[0-9]{3}$

예시:

ISBO_001
- I: 인카운터
- S: 스토리 인카운터
- B: 기지에서 발생
- O: 1회성
- 001: ISBO 조합의 첫 번째 데이터

IRSC_003
- I: 인카운터
- R: 랜덤 인카운터
- S: 수면 중 발생
- C: 쿨다운 방식
- 003: IRSC 조합의 세 번째 데이터

CMEB_001
- C: 캐릭터
- M: 주요 인물
- E: 기술 전문
- B: 기지 소속
- 001: CMEB 조합의 첫 번째 데이터

사용하지 않는 분류 자리에는 X를 사용한다.

예:
FXXX_001 = 시설 데이터 1번
RXXX_001 = 자원 데이터 1번
XXXX_001 = 계산식 데이터 1번

각 문자의 실제 의미와 허용 조합은 config/id_code_rules.json에서 관리한다.
한 번 사용한 ID는 이름이나 내용이 바뀌더라도 변경하지 않는 것이 좋다.
삭제한 ID의 번호 역시 다른 데이터에 재사용하지 않는 것을 권장한다.


======================================================================
4. 시간 규칙
======================================================================

게임 최대 기간: 1000일
하루 슬롯 수: 48
한 슬롯: 30분
전체 슬롯: 48000

day_index
- 내부 날짜 좌표다.
- 범위는 0~999다.
- 화면에는 day_index + 1로 표시한다.
- day_index 0은 DAY 1이다.

slot_index
- 하루 안의 시간 좌표다.
- 범위는 0~47이다.

시간 예시:
0  = 00:00
1  = 00:30
12 = 06:00
27 = 13:30
44 = 22:00
47 = 23:30

절대 슬롯 계산:
absolute_slot = day_index * 48 + slot_index

절대 슬롯은 행동 종료 시각, 일정 충돌, 업무 완료 시각, 쿨다운을 비교할 때 사용한다.


======================================================================
5. 공통 조건 구조: requirements
======================================================================

requirements는 행동, 업무, 인카운터, 장소, 아이템 등이 현재 사용 가능한지 검사한다.
필드가 없는 경우 해당 조건을 검사하지 않는다. 기본적으로 작성된 모든 조건을 동시에
만족해야 한다.

required_flags
- 반드시 참 또는 활성 상태여야 하는 플래그 키 배열이다.

excluded_flags
- 활성 상태이면 해당 콘텐츠를 사용할 수 없게 만드는 플래그 키 배열이다.

required_item_ids
- 반드시 보유해야 하는 아이템 ID 배열이다.

required_character_ids
- 반드시 존재하거나 사용 가능해야 하는 캐릭터 ID 배열이다.

required_facility_ids
- 반드시 존재하고 작동해야 하는 시설 ID 배열이다.

minimum_values
- 상태 경로별 최솟값을 정의한다.
- 예: "commander.health": 10.0

maximum_values
- 상태 경로별 최댓값을 정의한다.

time_ranges
- 발생 가능한 하루 시간대 목록이다.
- start_slot과 end_slot을 사용한다.

condition_formula_id
- 단순한 AND 조건으로 표현하기 어려운 복합 조건식을 참조한다.
- null이면 별도 조건 계산식을 사용하지 않는다.


======================================================================
6. 공통 효과 구조: effect
======================================================================

효과는 상태값 변경, 아이템 추가, 플래그 설정 등을 나타낸다.

target
- 변경할 대상 경로다.

대상 경로 예시:
commander.stress
character:CMEB_001.fatigue
facility:FXXX_001.condition
resource:RXXX_001.current_value
flag.generator_access
inventory.items

operation
- 대상에 적용할 연산이다.

지원 연산:
set       = 값을 교체한다.
add       = 값을 더한다.
subtract  = 값을 뺀다.
multiply  = 값을 곱한다.
divide    = 값을 나눈다.
add_id    = ID 배열에 값을 추가한다.
remove_id = ID 배열에서 값을 제거한다.

value
- 연산에 사용할 직접 값이다.

value_formula_id
- 직접 value 대신 계산식 결과를 사용한다.

clamp
- 변경 결과를 minimum과 maximum 범위 안으로 제한한다.

requirements
- 해당 효과가 실제로 실행되기 위한 추가 조건이다.

7. config/id_code_rules.json
======================================================================

[목적]
조합형 ID의 각 문자 위치에 어떤 알파벳을 사용할 수 있는지 정의한다.
ID 유효성 검사의 유일한 기준 파일이다.

[필드]

id_pattern
- 전체 ID 문자열의 정규식이다.

reserved_sequence
- 일반 데이터에 사용하지 않을 예약 일련번호다.

unused_code
- 사용하지 않는 분류 자리에 넣는 문자다. 현재 X다.

data_types
- 첫 번째 문자별 데이터 종류와 나머지 자리의 허용 문자를 정의한다.

name
- 코드가 나타내는 데이터 종류의 내부 이름이다.

positions
- 2, 3, 4번째 문자의 허용 코드와 의미다.

[처리]
데이터를 읽을 때 ID 정규식만 검사하지 말고, 첫 문자에 해당하는 positions 규칙까지
검사해야 한다.

8. config/game_config.json
======================================================================

[목적]
게임 전체에서 사용하는 시간 상수, 시작 시각, 핵심 데이터 경로를 정의한다.

[game 필드]

max_days
- 최대 날짜 수다. 현재 1000이다.

slots_per_day
- 하루 슬롯 수다. 현재 48이다.

minutes_per_slot
- 한 슬롯의 실제 분 수다. 현재 30이다.

start_day_index
- 새 게임 시작 날짜 좌표다.

start_slot_index
- 새 게임 시작 시간 좌표다.

id_pattern
- 모든 데이터 ID의 기본 정규식이다.

[paths 필드]

initial_state
- 초기 상태 JSON 경로다.

timetable
- 시간표 JSON 경로다.

id_code_rules
- ID 문자표 JSON 경로다.


======================================================================
9. initial/initial_game_state.json
======================================================================

[목적]
create_new_game()이 읽을 새 게임 초기 상태를 정의한다.
이 파일은 모든 데이터 정의를 복사해 넣는 파일이 아니라, 사용할 ID와 초기 덮어쓰기
값을 연결하는 진입점이다.

[필드]

current_time
- day_index와 slot_index로 시작 시각을 지정한다.

commander_id
- 책임자로 사용할 캐릭터 ID다.

active_character_ids
- 새 게임에 참여하는 캐릭터 ID 목록이다.

resource_values
- 자원 ID별 시작 수량이다.

facility_states
- 시설 ID별 시작 condition, efficiency, operational 값을 덮어쓴다.

character_overrides
- 캐릭터 정의의 default_state 위에 적용할 시작 상태다.

initial_task_ids
- 게임 시작과 동시에 활성화할 업무 정의 ID 목록이다.

active_pool_ids
- 시작할 때 런타임에 복사할 인카운터 풀 ID 목록이다.

inventory
- 아이템 ID와 시작 수량의 사전이다.

clue_ids
- 시작부터 알고 있는 단서 ID 목록이다.

deduction_ids
- 시작부터 완료된 추론 ID 목록이다.

flags
- 플래그 키와 시작값의 사전이다.

[create_new_game() 처리 순서]
1) 모든 정의 JSON을 읽는다.
2) ID와 참조를 검사한다.
3) 캐릭터 및 시설 default_state를 깊은 복사한다.
4) character_overrides와 facility_states를 적용한다.
5) resource_values를 현재 자원에 대입한다.
6) initial_task_ids로 런타임 업무를 생성한다.
7) active_pool_ids를 런타임 인카운터 풀로 깊은 복사한다.
8) 시간표를 연결한다.
9) 완성된 런타임 상태를 다시 검사한다.

10. timeline/timetable.json
======================================================================

[목적]
1000일 동안 특정 시각에 배치된 일정과 사건을 정의한다.

[저장 방식]
논리적으로는 time_table[day_index][slot_index]이지만, 48000개의 빈 칸을 모두 저장하지
않는다. 일정이나 사건이 있는 슬롯만 기록하는 희소 구조를 사용한다.

[필드]

max_days
- 시간표가 지원하는 전체 날짜 수다.

slots_per_day
- 하루 슬롯 수다.

days
- 특정 날짜에만 존재하는 예약 데이터를 담는다.

day_index
- 해당 날짜 좌표다.

slots
- 슬롯 번호를 문자열 키로 사용하는 객체다.

fixed_schedule_ids
- 해당 시각에 실행할 고정 일정 ID 목록이다.

scheduled_encounter_ids
- 해당 시각에 예약된 인카운터 ID 목록이다.

task_completion_ids
- 해당 시각에 완료 예정인 런타임 업무 인스턴스 ID 목록이다.

repeating_schedules
- 매일 또는 일정 간격으로 반복되는 고정 일정을 정의한다.

schedule_id
- 반복할 고정 일정 ID다.

start_day_index / end_day_index
- 반복이 적용되는 날짜 범위다.

slot_index
- 반복 일정 시작 시각이다.

interval_days
- 며칠마다 반복할지 나타낸다. 1이면 매일이다.

11. base/resources.json
======================================================================

[목적]
식량, 식수, 산소, 전력, 부품, 의약품 같은 자원을 정의한다.

[필드]

id
- 자원 ID다.

name
- UI에 표시할 자원 이름이다.

unit
- kg, L, %, 개 등의 표시 단위다.

value_type
- int 또는 float 등 값의 논리적 자료형이다.

minimum / maximum
- 자원이 가질 수 있는 값의 범위다.

default_value
- 별도의 초기값이 없을 때 사용할 기본값이다.

production_per_slot
- 정상 상태에서 30분마다 생산되는 양이다.

consumption_per_slot
- 정상 상태에서 30분마다 소비되는 양이다.

critical_threshold
- 부족 경고와 관련 인카운터 조건에 사용할 임계값이다.

display_as_percentage
- true이면 UI에서 백분율로 표시한다.

12. base/facilities.json
======================================================================

[목적]
발전 시설, 산소 시설, 의료 시설 등 기지 시설의 기본 상태와 기능을 정의한다.

[필드]

id / name
- 시설 ID와 표시 이름이다.

facility_type
- power, oxygen, medical 등 시설 분류다.

default_state
- 시설의 기본 런타임 상태다.

condition
- 시설 내구 상태다. 기본 범위는 0~100이다.

efficiency
- 시설 효율이다. 생산량 계산에 사용할 수 있다.

operational
- 현재 작동 가능 여부다.

level
- 시설 업그레이드 단계다.

produces
- 생산하는 자원 ID와 슬롯당 양이다.

consumes
- 소비하는 자원 ID와 슬롯당 양이다.

related_task_ids
- 이 시설과 관련된 업무 정의 ID 목록이다.

tags
- 검색, 조건 검사, UI 분류에 사용할 문자열 태그다.

13. characters/characters.json
======================================================================

[목적]
책임자와 핵심 캐릭터의 고정 정의 및 기본 상태를 관리한다.

[필드]

id / name
- 캐릭터 ID와 표시 이름이다.

role
- commander, specialist, npc 등 게임 역할이다.

specialty
- command, engineering, medical, exploration, research, administration 등 전문 분야다.

default_state
- 새 런타임 캐릭터를 만들 때 복사할 기본 상태다.

alive
- 생존 여부다.

available
- 현재 업무 배정 가능 여부다.

location_id
- 현재 기본 위치 ID다.

health
- 신체 건강 상태다.

condition
- 전반적인 컨디션이다.

fatigue
- 피로도다. 높을수록 나쁜 값으로 사용한다.

stress
- 스트레스다. 높을수록 나쁜 값으로 사용한다.

trust
- 책임자에 대한 신뢰도다.

awake_slots
- 연속으로 깨어 있던 30분 슬롯 수다.

judgement_reliability
- 판단 및 보고의 신뢰성을 나타낸다.

injury_level
- 부상 단계다.

skills
- 분야별 능력값이다. 업무 계산식에서 assignee.skill로 전달될 수 있다.

trait_ids
- 캐릭터가 가진 고정 특성 ID 목록이다.

starting_task_ids
- 게임 시작과 동시에 담당하게 할 업무 ID 목록이다.

14. characters/traits.json
======================================================================

[목적]
완벽주의, 겁이 많음, 낙관적 등 캐릭터의 비교적 고정적인 특성을 정의한다.

[필드]

id / name / description
- 특성 ID, 표시 이름, 설명이다.

19. formulas/formulas.json
======================================================================

[목적]
업무 성공 점수, 업무 시간, 조건 판정 등을 데이터로 정의한다.
JSON 자체는 계산하지 않으며 Godot FormulaEvaluator가 expression을 해석한다.

[필드]

id / name / description
- 공식 ID, 이름, 인간용 설명이다.

result_type
- float, int, bool 등 예상 결과 자료형이다.

expression
- 연산자와 값으로 구성된 표현식 트리다.

clamp
- 최종 결과를 minimum과 maximum 사이로 제한한다.

fallback_value
- 계산 중 오류가 발생했을 때 사용할 안전한 기본값이다.

[값 노드]

constant
- 고정값이다.
- 예: { "constant": 0.2 }

variable
- 계산 문맥에서 가져올 변수 경로다.
- 예: { "variable": "assignee.fatigue" }

[연산 노드]

operator
- 실행할 연산자 이름이다.

values
- 연산에 전달할 값 또는 하위 연산 노드의 배열이다.

[숫자 연산자]

add
- values를 모두 더한다.

subtract
- 첫 값에서 이후 값을 순서대로 뺀다.

multiply
- values를 모두 곱한다.

divide
- 첫 값을 이후 값으로 순서대로 나눈다.
- 0으로 나눌 가능성이 있으면 fallback_value를 사용해야 한다.

minimum / maximum
- values 중 최솟값 또는 최댓값을 반환한다.

clamp
- 값을 지정 범위로 제한한다.

floor / ceil / round
- 내림, 올림, 반올림한다.

[조건 연산자]

equal / not_equal
- 두 값이 같거나 다른지 검사한다.

greater / greater_or_equal
- 첫 값이 두 번째 값보다 큰지 또는 크거나 같은지 검사한다.

less / less_or_equal
- 첫 값이 두 번째 값보다 작은지 또는 작거나 같은지 검사한다.

and / or / not
- 불리언 조건을 조합한다.

[안전 규칙]
- 허용 목록에 없는 연산자와 변수 경로는 로딩 단계에서 거부한다.
- 표현식 트리의 최대 깊이를 32 정도로 제한한다.
- 계산식끼리 순환 참조하지 못하게 한다.
- 임의 문자열을 GDScript 코드로 실행하지 않는다.

21. encounters/encounter_pools.json
======================================================================

[목적]
행동과 환경별 출력 인카운터 목록 및 개별 가중치를 정의한다.

[필드]

id / name
- 인카운터 풀 ID와 이름이다.

category
- sleep, base_management, outdoor 등 풀의 용도다.

draw_mode
- 인카운터 추출 방식이다.

reset_policy
- 제거된 런타임 풀을 언제 다시 채울지 나타낸다.

encounters
- 풀에 포함된 인카운터 ID, weight, enabled 목록이다.

weight
- 상대적인 추첨 가중치다. 0 이상이어야 한다.

enabled
- false이면 정의는 유지하지만 현재 추첨 후보에서 제외한다.

[draw_mode]

weighted_with_replacement
- 가중치 추첨 후에도 항목을 풀에 남긴다.

weighted_without_replacement
- 가중치 추첨 후 선택 항목을 런타임 풀에서 제거한다.

sequential
- 배열 순서대로 선택한다.

shuffle_bag
- 전체 항목을 섞어 중복 없이 한 번씩 뽑은 뒤 다시 채운다.

[reset_policy]

never
- 자동으로 다시 채우지 않는다.

daily
- 날짜가 바뀔 때 원본 풀에서 다시 복사한다.

when_empty
- 런타임 풀이 비었을 때 다시 채운다.

on_action_start
- 해당 행동을 시작할 때 다시 채운다.

manual
- 코드 또는 인카운터 결과가 명시적으로 지시할 때만 다시 채운다.

[가중치 추첨 함수 처리]
1) enabled가 true인 항목을 수집한다.
2) 현재 조건을 만족하지 않는 인카운터를 제외한다.
3) 완료된 1회성 인카운터와 쿨다운 중인 인카운터를 제외한다.
4) 유효 항목의 weight 총합을 계산한다.
5) 총합이 0이면 인카운터 없음으로 처리한다.
6) 0 이상 총합 미만의 난수를 생성한다.
7) 배열 순서대로 가중치를 누적한다.
8) 난수가 누적값보다 작은 첫 항목을 선택한다.
9) without_replacement이면 런타임 배열에서 pop_at(index)로 제거한다.
10) with_replacement이면 항목을 제거하지 않는다.

중요: JSON에서 읽은 원본 encounters 배열에 직접 pop_at()을 호출하면 안 된다.
반드시 duplicate(true)로 만든 런타임 복사본에서 제거해야 한다.

27. JSON 로딩 및 유효성 검사 순서
======================================================================

권장 로딩 순서:

1) config/game_config.json
2) config/id_code_rules.json
3) 나머지 모든 정의 JSON
4) timeline/timetable.json
5) initial/initial_game_state.json
6) create_new_game()으로 런타임 상태 조립

파일 검사:
- JSON 문법이 올바른가
- schema_version이 지원되는가
- data_type이 파일과 일치하는가
- 필수 필드가 존재하는가
- 각 값의 자료형이 올바른가

ID 검사:
- ABCD_001 형식인가
- 각 위치 문자가 id_code_rules.json에 등록되어 있는가
- 파일 data_type과 ID 첫 문자가 일치하는가
- 중복 ID가 없는가
- 참조한 모든 ID가 존재하는가

시간 검사:
- day_index가 0~999인가
- slot_index가 0~47인가
- 행동 및 일정 시간이 정수 슬롯인가
- 반복 일정 날짜 범위가 올바른가

수치 검사:
- minimum이 maximum보다 크지 않은가
- 기본값과 현재값이 허용 범위 안인가
- duration_slots가 필요한 경우 1 이상인가
- 인카운터 weight가 0 이상인가
- 활성 풀의 유효 가중치 총합이 0보다 큰가

계산식 검사:
- 등록된 연산자만 사용하는가
- 등록된 변수 경로만 사용하는가
- 연산자별 피연산자 수가 올바른가
- 결과 자료형이 result_type과 맞는가
- 0으로 나누는 상황이 처리되는가
- 표현식 순환 참조가 없는가

콘텐츠 일관성 검사:
- 인카운터 ID 분류와 category가 일치하는가
- 인카운터 ID 반복 분류와 repeat_policy가 일치하는가
- 업무 outcome_table이 minimum_score 내림차순인가
- one_time 인카운터가 영구 반복하도록 잘못 설정되지 않았는가
- stackable이 false인 아이템의 maximum_stack이 1인가

28. 현재 템플릿 사용 시 주의사항
======================================================================

현재 폴더의 JSON은 형식 예시를 보여주는 템플릿이다. 일부 파일에는 아직 실제 정의가
추가되지 않은 ID 참조가 포함될 수 있다. 예를 들어 비활성 인카운터 풀 항목이나 앞으로
제작할 스토리 인카운터가 이에 해당한다.

실제 게임에서 전체 참조 유효성 검사를 켜기 전에는 다음 중 하나를 수행해야 한다.

1) 참조된 ID의 실제 정의를 추가한다.
2) 아직 사용하지 않는 참조 항목을 삭제한다.
3) 개발 중 미완성 참조를 허용하는 별도의 경고 모드를 사용한다.

출시 빌드에서는 누락 참조를 경고가 아니라 오류로 처리하는 것을 권장한다.

29. 수정 시 최종 체크리스트
======================================================================

[ ] JSON에 // 또는 /* */ 주석을 넣지 않았는가
[ ] 후행 쉼표가 없는가
[ ] ID가 조합형 문자표에 맞는가
[ ] ID가 중복되지 않는가
[ ] 참조한 ID가 실제로 존재하는가
[ ] 시간값이 30분 슬롯 정수인가
[ ] day_index와 slot_index 범위가 올바른가
[ ] 효과 대상 경로가 등록된 형식인가
[ ] 계산식이 허용된 연산자만 사용하는가
[ ] 인카운터 가중치가 0 이상인가
[ ] 원본 JSON 배열을 런타임에서 직접 수정하지 않는가
[ ] 새 게임 초기값이 정의 기본값과 의도대로 결합되는가
[ ] JSON 파싱 검사를 통과했는가
