# 1. 현재 버전의 확인된 문제

## 1.1 실행 해상도가 1920×1080이 아님

현재 `project.godot`에는 다음 설정이 있다.

```ini
window/size/viewport_width=1920
window/size/viewport_height=1080
window/size/window_width_override=1600
window/size/window_height_override=900
```

기준 뷰포트만 1920×1080이고 실제 창은 1600×900으로 열린다.

수정:

```ini
window/size/window_width_override=1920
window/size/window_height_override=1080
```

또는 override를 제거하되 실행 직후 실제 창이 1920×1080이 되게 한다.

제출 시 실제 실행 화면 PNG를 포함한다.

```text
docs/screenshots/main_1920x1080.png
```

검사 스크립트에서 이미지 크기가 정확히 1920×1080인지 확인한다.

1600×900 캡처의 확대본은 인정하지 않는다.

# 2. 왼쪽 자원 패널 삭제 또는 재설계

현재 왼쪽 패널은 플레이어가 판단해야 할 결론을 직접 알려준다.

삭제할 문구 예:

```text
저장량은 당장 충분함
생산량 감소 중
예상 위험: 며칠 안에 배급 조정 필요
여유가 적음
불안정
보고 불일치가 공개되면 불안이 커질 수 있음
```

이 문구들은 내부 시스템의 해석이거나 미래 예측이다.

메인 화면에서는 **결론형 자원 요약을 제거**한다.

## 대체 구조: 사건 자료철

왼쪽을 항상 같은 자원 목록으로 사용하지 않는다.

현재 사건에 필요한 원자료만 보여준다.

정수 시설 사건 예:

```text
05:10  자동 유량 118 L/h
05:40  자동 유량 109 L/h
06:10  기록 없음
```

```text
양동하 수기
“표시값하고 실제 유량이 안 맞는다.
필터 문제면 소리가 달라야 한다.”
```

```text
배급실 문의
05:52  세척수 압력 문의
06:03  주방 급수 지연
```

여기에는 “물이 부족하다”는 결론을 쓰지 않는다.

플레이어는 수치 변화, 누락 기록, 증언을 보고 직접 의심해야 한다.

## 정보 출처 표시

자료마다 다음을 표시한다.

- 출처
- 기록 시각
- 작성자
- 자동 기록인지 수기인지
- 마지막 갱신 시각
- 원문인지 요약인지

# 3. 중앙 사건 화면 수정

현재 다음 문구는 지나치게 설명적이고 AI가 만든 튜토리얼처럼 보인다.

```text
현재 정보 신뢰도: 불확실
전자 기록과 아날로그 기록이 충돌한다.
확인 방법
선택은 자동으로 실행되지 않는다
```

수정 방향:

- `신뢰도` 상자를 삭제
- 전자 기록과 수기 기록을 실제 문서처럼 나란히 배치
- 불일치는 플레이어가 눈으로 확인하게 함
- 확인 행동은 선택지에 자연스럽게 포함
- 메타 설명은 제거

예시:

```text
전자 운영 보고 / 06:00
정수 설비: 정상 범위

시설실 수기 / 양동하 / 05:32
유량 표시값 불일치.
독립 계측 전까지 분해 금지.
```

선택지:

```text
독립 유량계를 가져간다
양동하를 호출한다
지난 사흘의 수기 기록을 꺼낸다
오전 보고를 계속한다
```

버튼에 모든 결과를 설명하지 않는다.

시간 정보는 필요할 때 작은 보조 문구로 표시한다.

# 4. AI 대시보드 외형 제거

현재 문제:

- 모든 영역이 같은 둥근 카드
- 안전한 짙은 배경과 청록색 테두리
- 좌·중앙·우 대칭 3열
- 모든 섹션에 제목과 부제
- 동일한 문장 길이
- 기능을 계속 설명하는 안내 문구
- 화면 하단의 상시 핵심 문장

수정:

- 중앙 사건 문서가 화면의 65% 이상을 차지
- 왼쪽 자료철은 문서 조각이나 기록 탭 형태
- 우측 일정은 얇은 장부형 세로 열
- 둥근 카드 수를 절반 이하로 감소
- 각 패널의 모서리, 여백, 선 굵기를 동일하게 만들지 않음
- 종이 기록, 전자 보고, 책임자 메모의 표면을 다르게 처리
- 장식용 격자 배경을 약화하거나 제거
- 의미 없는 영문 장식 금지
- 하단의 `당신이 관리해야 할 마지막 자원은 당신 자신이다.` 상시 문구 삭제
- `ESC 닫기 · 키보드 포커스 지원` 같은 개발 안내는 첫 실행 도움말 또는 설정 화면으로 이동

# 5. 문체 수정

모든 UI 문장을 한 명의 설명자가 쓴 것처럼 만들지 않는다.

## 홍예슬

```text
오전 정수 점검이 길어질 경우 배급 회의는 대리 진행 가능.
산소 순환기 점검과 인력 충돌 있음.
```

## 양동하

```text
유량계 값 안 맞음.
필터 문제면 소리가 달라야 함.
열기 전에 독립 계측부터.
```

## 방준연

```text
업무 지속 권고하지 않음.
마지막 수면 시각 확인 필요.
```

## 김동현

```text
05:47에 같은 대역에서 짧은 신호 하나 더 잡힘.
잡음으로 보기엔 간격이 일정하다.
```

텍스트는 자연스럽고 짧게 작성한다.

같은 형식의 세 문장, 동일한 길이의 목록, 지나친 정리 문구를 피한다.

# 6. 책임자 상태 표시

기본 상태 버튼에서 다음처럼 결론을 한 번에 모두 보여주지 않는다.

```text
피곤함
스트레스 높음
판단 신뢰도: 정확히 알 수 없음
```

메인 화면에서는 징후만 보여준다.

예:

```text
06:04에 적은 메모를 다시 읽었다.
같은 보고서를 두 번 열었다.
마지막 수면 시각은 확실하지 않다.
```

상태 화면에 들어가면 다음을 구분한다.

- 주인공이 느끼는 것
- 근무 기록이 보여주는 것
- 동료가 관찰한 것
- 의료 검사 결과
- 아직 모르는 것

의료 검사 전에는 정확한 진단을 표시하지 않는다.

---

# 7. 자원 총괄 화면

자원 정보가 필요 없다는 뜻은 아니다.

메인 사건 화면에서 결론형 요약을 제거하고, 별도의 `운영 장부` 화면에 둔다.

운영 장부에서는 다음을 제공한다.

- 원자료
- 최근 조사 시각
- 소비 기록
- 생산 기록
- 배급 기준
- 기록 누락
- 담당자 작성 요약

플레이어가 `요약 요청`을 눌렀을 때 홍예슬 또는 담당자가 결론을 작성할 수 있다.

그 결론은 작성자의 판단이며 절대적인 시스템 문구가 아니다.

# 9. godot_data_core 연결

별도의 새로운 데이터 규격을 만들지 않는다.

실행 데이터의 기본 구조:

```json
{
  "schema_version": 1,
  "data_type": "...",
  "entries": []
}
```

UI 전용 임시 데이터가 필요한 경우:

- `prototype_only: true` 표시
- 실행용 core 데이터와 분리
- README에 임시 데이터임을 기록
- 나중에 core repository로 교체할 위치를 명시

UI에서 내부 수치를 직접 출력하지 않는다.

표시 변환 계층을 둔다.

```text
core 내부값
→ 관측 가능 여부 확인
→ 출처와 정보 수준 적용
→ 화면 문구 생성
```

# 10. 검증 스크립트 보강

`tools/validate_project.py`에 다음 검사를 추가한다.

- 실제 창 override가 1920×1080인지
- 제출 PNG가 정확히 1920×1080인지
- 메인 화면 데이터에 금지 결론 문구가 없는지
- `forecast` 필드가 메인 자원 패널에 출력되지 않는지
- 상시 슬로건이 제거되었는지
- 정확한 책임자 퍼센트가 없는지
- 정확한 식량 kg가 메인 화면에 없는지

금지 문구 예:

```text
며칠 안에 배급 조정 필요
생산량 감소 중
현재 정보 신뢰도
선택은 자동으로 실행되지 않는다
필요한 정보만 펼쳐져 있다
```

문자열 하나를 기계적으로 바꾸는 데 그치지 말고, 원자료 중심 구조로 변경한다.
